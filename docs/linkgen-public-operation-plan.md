# LinkGen 公开运营准备与执行路线

调研日期：2026-08-11<br>
适用产品：LinkGen AI 社群微信小程序<br>
主体方案：拟以公司主体申请并运营
范围：主体、备案、数据存储、成员信息采集、内容治理、活动运营、Agent 采集和上线计划

> 这是一份产品与工程执行方案，不替代律师、通信管理局或微信平台的正式意见。涉及服务类目、增值电信业务许可证、个人信息保护影响评估的结论，提交前应以当前平台后台和属地主管部门答复为准。

## 一、先给结论

LinkGen 当前是可演示原型，不是可公开运营版本。主要原因：

| 当前状态 | 证据 | 公开运营风险 |
| --- | --- | --- |
| 帖子、活动、个人资料写入本地 Storage | `utils/linkgen-data.js` 的 `wx.getStorageSync` / `wx.setStorageSync` | 不同用户无法共享；清缓存即丢失；前端可篡改 |
| 小程序没有初始化 LinkGen 云环境 | `app.js` 只有 `seedLocalData()`，没有 `wx.cloud.init()` | 云函数和数据库无法成为正式数据源 |
| 现有云函数主要是菜单、订单、登录 | `cloudfunctions/createOrder`、`menuList`、`manageMenu` 等 | 不是 LinkGen 的帖子、活动、成员后端 |
| Agent 和链接解析是演示数据 | `pages/admin-review/admin-review.js` 直接生成本地候选活动 | 无法证明来源真实、授权、字段准确或可追溯 |
| 没有完整举报、封禁、数据删除和审计流程 | 现有页面未发现对应服务端能力 | UGC 社区无法持续履行平台治理责任 |

### 推荐运营形态

| 阶段 | 公开范围 | 主体建议 | 允许功能 |
| --- | --- | --- | --- |
| 体验 Demo | 仅开发者和熟人 | 个人主体可用于体验 | 本地演示数据，不收集真实成员资料 |
| 邀请制 Beta | LinkGen 社群成员 | 公司主体 | 实名后台、发帖审核、成员目录登录可见、活动报名 |
| 公开运营 | 社群外用户也可进入 | 一人有限责任公司或其他合适公司主体 | 完整 UGC、活动聚合、Agent、运营后台、申诉与数据权利 |

建议路径：本项目按公司主体申请、开发和运营。若公司尚未成立，先完成公司设立和平台主体准备，再进入真实数据开发；等待期间只运行本地 Demo，不收集真实成员资料。公司主体不等于自动取得业务许可，服务类目、备案、许可证和数据合规仍需分别确认。

## 二、必须区分的三个概念

### 1. 小程序备案

这是互联网信息服务备案。工信部《工业和信息化部关于开展移动互联网应用程序备案工作的通知》（工信部信管〔2023〕105号）将小程序列入移动互联网应用程序分发范围，要求境内从事互联网信息服务的 APP 主办者履行备案手续；通知同时明确小程序等分发平台和主办者的责任。

办理入口：

- [工信部 ICP/IP 地址/域名信息备案管理系统](https://beian.miit.gov.cn/)
- 小程序管理后台通常在「设置 / 基本设置 / 小程序备案」进入，以当前后台显示为准。

备案通常需要：主体真实信息、负责人信息、证件、联系方式、服务名称、服务内容、承诺书、平台要求的真实性核验材料。资料名称和核验方式可能随主体类型和省份变化。

备案不是业务许可。备案完成不等于已经取得社交、论坛、新闻、出版、支付或其他业务许可。

### 2. ICP 备案与增值电信业务许可证

| 项目 | 含义 | LinkGen 判断 |
| --- | --- | --- |
| ICP 备案 | 非经营性互联网信息服务的备案记录 | 公开上线前按小程序和所用域名/服务链路办理 |
| 增值电信业务许可证 | 经营性互联网信息服务等业务许可 | 是否需要取决于服务类目、收费、广告、平台撮合等实际模式，不能用“只是小程序”判断 |
| 微信服务类目资质 | 微信平台上架审核要求 | 在小程序后台选择最接近“社交/社区/内容/活动”的类目，查看当时的资质清单 |

不要用“先选一个容易过审的类目，实际上做另一类业务”的方式上线。提交前保存服务类目、资质要求和审核结果截图；如果后台提示需要许可证，向微信官方支持和主体所在地通信管理局确认。

### 3. UGC 内容治理

LinkGen 有发帖、评论、成员介绍、活动提交，属于用户生成内容场景。中央网信办发布的《互联网跟帖评论服务管理规定》明确要求：

- 后台实名、前台自愿；未完成真实身份认证的用户，不应提供跟帖评论服务。
- 建立用户信息保护制度，告知收集目的、方式、范围并取得同意。
- 建立审核管理、实时巡查、应急处置制度。
- 配备与服务规模相适应的审核队伍。
- 提供便捷投诉举报入口，及时受理和处置。
- 对违规内容采取警示、拒绝发布、删除、限功能、暂停更新、关闭账号等措施，并保存记录。

因此，LinkGen 不能只做“发帖按钮 + 数据库”。发布、评论、举报、审核、封禁和日志必须一起设计。

## 三、主体和账号准备

### 推荐主体

| 方案 | 优点 | 风险 | 建议 |
| --- | --- | --- | --- |
| 个人主体 | 成本最低 | 服务类目、支付、资质和责任承接受限；个人与平台责任混在一起 | 只做 Demo，不作为公开社区长期方案 |
| 个体工商户 | 办理快、成本低 | 经营者承担个人经营责任；后续资质和融资能力有限 | 邀请制 Beta 可选 |
| 一人有限责任公司 | 主体清晰，便于签场地合作、申请资质、收款、招聘运营人员 | 有注册、记账、年报和税务成本 | 正式公开运营首选 |
| 借用他人公司 | 可快速上线 | 实际运营者、备案主体、数据责任人不一致 | 不采用 |

### 公司申请的具体决策

1. 如果当前只有一位发起人，可优先评估一人有限责任公司；如果已有联合发起人，先明确股权、法定代表人、实际运营负责人和退出安排，再决定公司形式。最终以登记机关、会计师或律师的最新意见为准。
2. 公司经营范围、微信小程序服务类目和实际功能必须一致。LinkGen 当前涉及社区内容、评论、活动发布、成员名片和外部活动聚合，不要用无关类目包装真实业务。
3. 公司成立后，用公司主体重新核对微信公众平台、小程序、腾讯云、域名、邮箱和支付账户的归属；不要默认个人主体的 AppID、备案或云环境可以直接沿用。
4. 公司需要维护基本的税务申报、年报、发票和合同管理。即使首版不收费，也要保留场地合作、服务商委托、隐私处理和内容审核相关的合同记录。
5. 不借用他人公司代持小程序。实际运营者、用户数据责任人、备案主体和收款主体不一致，会增加平台审核、数据权利请求和纠纷处理风险。

### 账号清单

1. 微信公众平台账号：以公司主体新建或按平台规则完成主体变更；配置管理员、运营者、财务联系人。
2. 小程序 AppID：当前项目 `project.config.json` 中已有 AppID，先确认归属主体；如属于个人主体，先向微信平台确认主体变更/迁移条件，不要直接用于公司公开运营。
3. CloudBase 账号：腾讯云账号、环境管理员、开发者、运营审核员分权。
4. 域名与备案主体：只在需要服务端 API、后台、外链解析时配置；域名、主体和实际服务要一致。
5. 内容审核账号：开通微信内容安全能力或腾讯云内容安全服务，密钥只放服务端。
6. 运营邮箱：处理举报、隐私请求、账号申诉、活动纠纷和数据删除请求。
7. 运营后台账号：至少分为超级管理员、内容审核员、活动运营、只读审计员。

### 公司现在需要提供的资料包

公司作为小程序主体和实际运营者，不能只提供营业执照“挂名”。公司需要确认愿意承担账号管理、用户数据处理、内容审核、活动纠纷和用户投诉责任。

| 资料/决定 | 公司需要提供 | 格式/要求 | 负责人 |
| --- | --- | --- | --- |
| 主体证照 | 营业执照、统一社会信用代码、注册地址、成立日期、经营范围 | 清晰扫描件；以当前微信后台要求为准 | 公司负责人 |
| 主体负责人 | 法定代表人姓名、证件信息、手机号、邮箱 | 只提交到官方后台或受托服务商，不进 GitHub | 公司负责人 |
| 小程序管理员 | 管理员姓名、微信号、手机号、可接收验证码的设备 | 至少 1 名公司长期人员；不要使用临时开发者账号 | 公司负责人 |
| 运营联系人 | 客服邮箱、投诉举报邮箱、隐私联系人、应急电话 | 对外公开的联系方式保持长期可用 | 运营负责人 |
| 账号归属 | 微信公众平台账号、当前 AppID `wx3cf9f61d12f83836` 的主体归属 | 核对是否属于公司；不一致时先确认迁移/重新注册条件 | 公司负责人 + 研发 |
| 腾讯云账号 | 公司实名认证腾讯云账号、账单联系人、环境管理员、开发者、审计员 | 生产权限分权；不共用个人主账号 | 公司负责人 + 研发 |
| 业务边界 | 首版是否收费、广告、支付、抽佣、活动报名收费、对外开放 | 形成一页纸确认，决定类目和资质核验范围 | 公司负责人 + 运营 |
| 内容规则 | 社区公约、发帖/评论规则、活动安全提示、违规处理梯度 | 运营确认，法务/律师复核 | 运营 + 法务 |
| 隐私材料 | 用户协议、隐私政策、个人信息字段表、保存期限、删除/注销流程 | 真实功能和数据流向必须与文案一致 | 法务/隐私负责人 |
| 活动责任 | 主办方规则、地点合作/授权证明、取消改期规则、紧急联系人规则 | 线下活动必须明确责任边界 | 活动负责人 |
| 域名与服务 | 若有独立后台/API，提供域名、备案状态、服务器/服务商信息 | 域名、主体、服务用途保持一致 | 研发 |

### 小程序注册和备案资料清单

注册、主体认证、类目审核和备案是不同流程。后台页面会随地区、主体和服务类目调整，提交前以微信公众平台和属地主管部门当前要求为准。

| 流程 | 提前准备 | 产出/核验 |
| --- | --- | --- |
| 微信公众平台/小程序注册 | 公司证照、法定代表人/管理员信息、管理员微信和手机号、邮箱、小程序名称、简介、头像 | 公司主体小程序账号、AppID、管理员权限 |
| 主体认证 | 营业执照、主体联系人、验证方式及平台要求的认证材料 | 主体认证状态；认证主体必须是实际运营公司 |
| 服务类目 | LinkGen 功能说明：社区帖子、评论、成员目录、活动发布/报名、外部活动候选审核 | 选择最接近真实功能的类目，保存资质要求和审核截图 |
| 小程序备案 | 主体信息、负责人信息、服务名称、服务内容、承诺材料、平台要求的真实性核验 | 备案提交/通过状态、备案编号和展示位置 |
| 域名/服务器备案 | 只有使用独立域名、独立 API 或后台时准备域名和接入服务商资料 | 域名、主体、服务端归属一致；备案不替代业务许可证 |
| 隐私与用户协议 | 采集字段、用途、第三方服务、存储地域、保存期限、删除/注销和投诉方式 | 上线前可在小程序内打开并留存版本号 |
| UGC 能力核验 | 后台实名、内容审核、举报、申诉、封禁、巡查、审计记录的实现说明 | 平台审核材料和内部操作记录 |

**公司需要先交给项目组的最小资料包：**营业执照扫描件、法定代表人/管理员信息、公司主体下的 AppID、公司腾讯云账号、客服/投诉邮箱、公司确认的业务边界。证件原件、手机号、Token 和用户数据不通过聊天群或 GitHub 传递。

## 四、真实数据存储方案

### 数据具体放在哪里

| 数据类型 | 生产存放位置 | 测试存放位置 | 不能存放的位置 |
| --- | --- | --- | --- |
| 用户账号、数字名片、帖子、评论、活动、报名 | 中国大陆区域 CloudBase 生产环境的云数据库 | `linkgen-staging` CloudBase 数据库 | 小程序包、GitHub、个人电脑、浏览器 Local Storage |
| 头像、帖子图片、活动图片 | 中国大陆区域 CloudBase 生产环境的云存储，使用 `fileID` 和权限控制 | `linkgen-staging` 云存储 | README、截图目录、公开对象存储、GitHub |
| 审核任务、举报、封禁、操作记录 | CloudBase 数据库中的 `moderation_tasks`、`reports`、`audit_logs` 集合 | 测试环境对应集合 | 只放在前端页面或运营人员聊天记录 |
| Agent 运行记录、外部活动来源 | CloudBase 数据库中的 `agent_runs`、`source_items` 集合；原始抓取服务只保留必要字段 | 测试环境对应集合 | 小程序端密钥、公开仓库、无授权的全文转载库 |
| 密钥、API Token、数据库管理凭证 | 云函数环境变量或密钥管理服务 | 测试环境独立密钥 | `app.js`、`project.config.json`、GitHub、截图 |
| 本地演示数据 | 仅保留在开发者工具的本地 Storage，用于 Demo | 允许使用 | 不能作为真实用户生产数据 |

生产数据的唯一业务来源应是 `linkgen-production` CloudBase；小程序端只拿到经过云函数鉴权和字段白名单过滤的数据。当前项目的 `wx.getStorageSync` / `wx.setStorageSync` 只适合演示，不能承载真实用户数据。

### 推荐技术路线

使用微信小程序 + 中国大陆区域 Tencent CloudBase：

```text
微信小程序
  -- wx.login / 用户授权 --> 登录云函数
  -- 业务请求 --> LinkGen 云函数
  -- 服务端鉴权 --> CloudBase 数据库 / 云存储
  -- 审核任务 --> 内容安全服务 + 运营后台
  -- 定时任务 --> 来源白名单 / 解析服务 --> 候选活动
```

CloudBase 官方文档说明，一个环境包含独立的数据库实例、存储空间和云函数配置，并有唯一 EnvId。建议创建 `linkgen-staging` 和 `linkgen-production` 两个环境，均选择中国大陆区域，不把生产数据放在测试环境。

### 从注册到服务端上线：具体操作顺序

LinkGen 首版不需要单独购买 VPS。小程序前端发布到微信平台，数据库、图片和业务后端使用腾讯云 CloudBase；Agent 定时任务优先使用 CloudBase 定时触发器。只有长时间抓取、复杂队列或独立后台超出 CloudBase 能力时，才增加独立服务。

```text
公司微信主体 / AppID
        |
微信开发者工具上传小程序代码
        |
linkgen-production CloudBase
  ├─ 云函数：登录、帖子、评论、活动、报名、审核
  ├─ 云数据库：users / profiles / posts / events / moderation
  ├─ 云存储：头像、帖子图、活动图
  └─ 定时触发器：Agent 搜索 -> 候选活动 -> 人工审批
```

| 步骤 | 实际操作 | 完成标准 |
| --- | --- | --- |
| 1. 锁定主体 | 公司确认实际运营责任；核对 AppID 是否属于公司 | 主体、管理员、AppID、客服邮箱形成账号归属表 |
| 2. 注册与备案 | 在微信公众平台完成注册/认证；按后台提交类目和备案材料 | 账号认证、服务类目、备案状态可截图留档 |
| 3. 建云环境 | 公司腾讯云创建 `linkgen-staging`、`linkgen-production`，均选中国大陆区域 | 记录 EnvId、地域、套餐、管理员和备份策略 |
| 4. 配置小程序 | 开发者工具导入项目，确认 `project.config.json` 的 AppID；`app.js` 初始化 CloudBase | 测试环境能完成微信登录并取得服务端会话 |
| 5. 部署云函数 | 在开发者工具右键 LinkGen 云函数，选择“上传并部署：云端安装依赖”；先部署 staging，并配置 `LINKGEN_OWNER_OPENID` | 登录、帖子、评论、活动、报名、审核函数可调用；公开访客不能抢占 owner |
| 6. 建数据库 | 创建数据集合、索引、权限规则和字段白名单；管理员操作全部走云函数 | 普通用户、审核员、管理员越权测试通过 |
| 7. 配置云存储 | 建立头像、帖子图片、活动图片目录；默认私有读，前端使用 `fileID` 或短期链接 | 未授权用户不能读取私有图片；图片审核失败可重试 |
| 8. 导入测试数据 | 只将脱敏 Demo 数据导入 staging；`db-import/` 不得包含真实个人信息 | 能验证活动、帖子、成员、审核和报名全链路 |
| 9. 切换数据源 | 将 `utils/linkgen-data.js` 的生产调用迁移为云函数 API；生产环境关闭 `seedLocalData()` | 真机清缓存、换账号后数据仍能共享；无本地生产数据 |
| 10. 配置 Agent | 定时触发器执行来源白名单搜索/解析；结果写入 `source_items` 和候选集合 | Agent 只生成候选，运营审批后才能进入 `events` |
| 11. 生产发布 | staging 验收后配置生产 EnvId，部署云函数和小程序版本，提交微信审核 | 生产备份、告警、角色权限、回滚包均已验证 |

### 开发者工具中的部署动作

1. 安装微信开发者工具，使用公司小程序 AppID 导入项目根目录。
2. 在“云开发/云托管”中选择 `linkgen-staging`，不要直接连接生产环境开发。
3. 右键 `cloudfunctions/login`、帖子/活动/审核相关函数，执行“上传并部署：云端安装依赖”；每个函数的 `package.json` 保持可安装。
4. 在 CloudBase 控制台建立集合和权限；不要把数据库管理密钥写入 `app.js`、`project.config.json` 或小程序代码。
5. 使用 3 类账号验收：普通成员只能读公开字段；审核员只能处理审核队列；管理员才能改配置和查看审计日志。
6. staging 通过后，复制配置到生产环境，重新部署生产函数；不要把 staging 数据库直接改名当生产库。

**服务端切换的关键改造：**当前 `app.js` 即使初始化 CloudBase，仍会调用 `seedLocalData()`；这只能作为演示兜底。生产版本必须由登录云函数建立用户会话，所有写操作通过云函数完成，前端不直接持有全库读写权限。

### 数据集合

| 集合 | 关键字段 | 客户端权限 |
| --- | --- | --- |
| `users` | `_openid`、状态、首次登录时间、最近登录时间、同意版本 | 只能由云函数写入 |
| `profiles` | 昵称、头像 fileID、身份、城市、标签、介绍、加入目的、可见性 | 用户只能改自己的；公共读取只返回白名单字段 |
| `posts` | 作者 ID、标题、正文、标签、审核状态、发布时间、删除原因 | 用户创建待审核；发布和删除由云函数控制 |
| `comments` | 帖子 ID、作者 ID、正文、审核状态、回复关系 | 默认待审核；不能直接修改他人评论 |
| `events` | 时间、类型、地点、人数、来源、组织者、状态、审核信息 | 只读已发布；创建和审核走云函数 |
| `event_registrations` | 活动 ID、用户 ID、状态、报名时间、取消时间 | 只读自己的记录；运营看必要字段 |
| `reports` | 举报人、目标类型、目标 ID、原因、证据、处理状态 | 举报人只能看自己的进度 |
| `moderation_tasks` | 内容、风险等级、审核人、处理动作、时间 | 仅审核员和审计员 |
| `source_items` | 来源 URL、平台、摘要、内容 hash、抓取时间、授权状态 | 仅活动运营和 Agent 服务 |
| `agent_runs` | 任务参数、来源、开始结束时间、失败原因、候选数量 | 仅运营和审计员 |
| `admins` | openid、角色、状态、授权时间 | 仅超级管理员 |
| `audit_logs` | 操作人、动作、对象、前后状态、时间、IP/设备摘要 | 只增不改，审计员可读 |
| `consents` | 用户、协议版本、隐私政策版本、同意时间、撤回时间 | 仅服务端和审计员 |

### 安全原则

- 小程序端不能直接拥有全库读写权限；所有写操作通过云函数鉴权。
- `openid` 只用于服务端关联，不展示给其他成员，不写入 README、截图或公共接口响应。
- 手机号只用于后台实名、通知或账号找回；公共数字名片不展示手机号。
- 头像使用云存储 `fileID`，默认私有读或生成短期访问链接，不继续依赖本地 `wx.saveFile`。
- 生产、测试环境分离；生产管理员不共用个人开发者账号。
- 数据库、云函数、云存储、后台都开启最小权限；审核员不能导出全量个人信息。
- 配置每日备份、误删恢复演练、云函数错误告警和异常登录告警。
- 服务商、内容审核、短信、AI 解析等第三方接入前登记数据流向，签订委托处理和保密条款。

### 保存期限建议

| 数据 | 初始策略 | 到期动作 |
| --- | --- | --- |
| 账号与名片 | 账号存续期间 | 注销后删除或匿名化；保留法律要求的审计最小记录 |
| 已发布帖子/评论 | 账号存续期间及社区历史需要 | 用户删除后先软删除，申诉/安全记录单独按必要期限保存 |
| 未通过审核内容 | 90 天 | 删除正文和图片，仅保留必要的处理结果和风险标签 |
| 活动报名 | 活动结束后 12 个月 | 匿名化统计，删除不再需要的联系方式 |
| 举报与审核记录 | 建议 2 年起 | 根据事件、投诉和法律要求调整；由运营负责人确认 |
| 登录与安全日志 | 建议 6-12 个月 | 超期聚合或删除 |

保存期限不是法律统一固定值，必须写入隐私政策，并根据实际业务、争议和主管部门要求复核。

## 五、成员信息怎么采集

### 推荐入驻流程

```text
未登录
  --(阅读并同意用户协议/隐私政策)--> 微信登录
  --(后台建立用户)--> 填写数字名片
  --(选择公开范围)--> 待审核成员
  --(运营通过)--> 社区可见
  --(用户修改/撤回)--> 重新审核或隐藏
```

### 字段分层

| 字段 | 是否必填 | 公开范围 | 说明 |
| --- | --- | --- | --- |
| 微信身份关联、`openid` | 服务必需 | 不公开 | 云函数获取，不能让用户手填 |
| 昵称 | 必填 | 社区成员可见 | 用户主动填写，不强制使用微信昵称 |
| 头像 | 必填 | 社区成员可见 | 默认头像或用户上传，支持删除和切换 |
| 身份/职业 | 建议必填 | 社区成员可见 | 例如 AI 产品、设计师、工程师 |
| 城市 | 可选 | 可设为仅成员可见 | 只选城市，不采集精确定位 |
| 标签 | 可选 | 社区成员可见 | 最多 5 个，支持自定义但需要治理 |
| 个人介绍 | 可选 | 社区成员可见 | 限字数，发布前内容审核 |
| 加入目的 | 可选 | 社区成员可见 | 提供选项 + 自由文本，减少空泛内容 |
| 手机号 | 非默认 | 仅后台或本人 | 只有明确用途时单独授权和加密存储 |
| 微信号/外部联系方式 | 非默认 | 不公开 | 使用“交换联系方式”流程，双方确认后再展示 |
| 身份证、人脸、通讯录 | 禁止默认采集 | 不适用 | 除非未来特定资质明确要求并完成专项评估 |
| 精确位置、住址、行踪轨迹 | 禁止默认采集 | 不适用 | 活动地点使用场地文本或地图 POI，不保存实时位置 |

《个人信息保护法》要求合法、正当、必要、透明和最小范围；处理目的、方式、种类和保存期限需要清楚告知；用户拥有查阅、复制、更正、删除和撤回同意等权利。公开成员名片属于对外展示个人信息，默认只展示用户主动填写的低敏字段，并提供单独的可见性开关。

### 页面必须有的交互

1. 首次登录前展示《用户协议》和《隐私政策》；协议版本、时间、用户 ID 写入 `consents`。
2. `手机号`、`联系方式交换`、`公开名片`分别使用单独说明和单独同意，不用一个总勾选代替。
3. 个人中心提供“隐藏名片”“导出我的数据”“删除账号”“申请删除内容”“撤回联系方式授权”。
4. 运营后台提供查询、导出、删除和封禁操作的二次确认，并写入审计日志。
5. 用户注销后，公共内容可以按规则匿名化，而不是继续展示原昵称和头像。

- 数据导出、年度隐私报告、成员内容归档、公开社区规则变更记录。

## 七、Agent 和外部活动采集边界

外部公众号、小红书、活动平台内容不能默认当成可自由抓取和转载的公共数据。生产方案应满足：

1. 优先使用官方 API、合作方授权或用户主动粘贴的公开链接。
2. 不在小程序端放第三方密钥；解析、去重、限速和日志全部在服务端。
3. 只保存活动必要字段和来源 URL；不长期保存无关全文、图片或评论。
4. 显示“来源平台、来源链接、采集时间、最后核验时间”。
5. Agent 只生成候选，不直接发布；时间、地点、报名链接、主办方必须由运营确认。
6. 发现来源撤稿、活动取消、报名链接失效时，自动标记“待复核”，不继续推荐。
7. 对 robots、平台服务条款、著作权、个人信息和反爬限制逐来源建立白名单。
8. 如果未来让 AI 面向公众生成回答、推荐或内容，另行评估生成式人工智能、算法推荐、内容标识和安全管理要求；内部 Agent 候选不等于可以绕过这些要求。

## 八、公开运营执行路线

以下工期是工程估算，不是政府审核时限。

### 阶段 0：做一次产品边界确认，1 天

负责人：发起人 + 运营负责人

- 确认首版只做社群工具，不做支付、广告、打赏、抽佣和付费活动。
- 确认首版为邀请制 Beta，成员目录登录后可见。
- 确认以公司主体申请；确定公司名称、注册地址、法定代表人、实际运营负责人和客服邮箱。
- 确认隐私联系人、活动责任边界和公司成立前后的切换方案。
- 输出：功能范围、公司设立信息表、服务类目候选、数据字段表。

### 阶段 1：公司主体与备案材料，3-10 个工作日准备（不含登记机关和平台审核时长）

负责人：主体负责人

- 确定公司名称、注册地址、注册资本、股权结构、法定代表人和经营范围，完成公司设立登记。
- 公司成立后，注册/确认微信公众平台和小程序管理员，重新核对 AppID 归属和主体变更/迁移条件。
- 在后台检查“社交/社区/内容/活动”相关服务类目和资质。
- 准备营业执照、法定代表人和管理员证件、联系方式、服务说明、隐私政策地址或页面。
- 通过小程序后台进入备案流程，提交主体、负责人、服务和承诺材料。
- 同步确认域名、服务端、CloudBase、客服邮箱和后续支付账户使用公司主体；不符合条件的个人资产不要直接挂到生产链路。
- 需要许可证时，不要绕过审核；向微信平台和属地通信管理局确认。
- 建立公司的税务申报、年报、合同和数据处理记录负责人。
- 输出：营业执照及主体材料、备案申请、类目审核记录、账号归属表。

### 阶段 2：云环境与真实数据，5-10 个工作日

负责人：研发

- 创建 `linkgen-staging` 和 `linkgen-production` CloudBase 环境。
- 选择中国大陆区域，记录 EnvId、地域、套餐、备份策略和管理员。
- `app.js` 初始化 CloudBase；实现登录云函数，服务端获取 openid。
- 新建 `users`、`profiles`、`posts`、`comments`、`events`、`event_registrations`、`reports`、`admins`、`audit_logs` 等集合。
- 把页面从同步本地函数切换为异步云函数调用，先迁移活动，再迁移帖子和成员。
- 配置数据库规则，验证普通用户、审核员、管理员三类账号。
- 配置云存储私有读写、头像上传、图片内容审核、失败重试和备份。
- 输出：真实数据接口、权限矩阵、测试环境数据和回滚方案。

### 阶段 3：内容治理与协议，5-8 个工作日

负责人：运营 + 法务/律师复核

- 发布《用户协议》《隐私政策》《社区公约》《活动安全提示》。
- 确认后台实名方式；至少完成微信身份关联，必要时增加手机号验证。
- 建立敏感词、图片、链接、广告、诈骗、骚扰、违法活动的处理规则。
- 配置自动检测、人工审核、举报、申诉、封禁、解封和记录导出。
- 设定审核响应时限：普通举报 24 小时内，涉及人身安全、诈骗和违法信息立即升级。
- 建立数据查阅、更正、删除、注销和隐私投诉处理表单。
- 输出：规则文档、审核排班、事件升级表、协议最终版。

### 阶段 4：产品补齐与内部测试，7-15 个工作日

负责人：研发 + 设计 + 运营

- 完成登录、入驻申请、名片可见性、发帖/评论审核、举报和注销。
- 完成活动报名、候补、取消、提醒、过期和主办方管理。
- 完成运营后台四类审核队列和审计日志。
- 完成活动链接解析候选、Agent 候选、来源核验和重复合并。
- 使用 10-20 个测试账号验证越权、重复提交、删除、封禁、并发报名、图片审核和隐私展示。
- 输出：测试报告、已知问题清单、上线回滚包。

### 阶段 5：邀请制 Beta，至少 2 周

负责人：运营

- 先邀请 30-100 名真实成员，不开放全网自由发帖。
- 每天检查审核队列、举报、错误日志、活动失效率和报名纠纷。
- 每周复盘“注册 → 完善名片 → 浏览内容 → 报名活动 → 发布内容”漏斗。
- 不在 Beta 期间接入付费、广告、抽佣或公开手机号。
- 输出：真实用户反馈、审核工作量、留存和活动参与数据。

### 阶段 6：公开发布门槛

以下条件全部满足才扩大公开入口：

- 主体、类目、备案状态清晰并通过平台审核。
- 真实数据已在生产 CloudBase，未再依赖 `seedLocalData` 作为业务数据源。
- 用户协议、隐私政策、社区公约、举报和注销入口可访问。
- 后台实名、内容审核、实时巡查、封禁、举报和审计日志可验证。
- 生产备份、告警、权限分级、密钥和事件响应已演练。
- 30-100 名 Beta 用户连续两周无 P0/P1 隐私或越权问题。
- 外部活动来源有白名单和人工审批，Agent 不会直接发布。

## 十二、最终建议

LinkGen 不应直接从“本地 Demo”跳到“全网公开”。最稳妥的路线是：

```text
确认主体与功能边界
  --> 公司/个体工商户主体
  --> 小程序类目与备案确认
  --> 中国大陆 CloudBase 真实数据
  --> 后台实名 + 内容治理 + 隐私权利
  --> 30-100 人邀请制 Beta
  --> 两周运营复盘
  --> 公开扩量
```

当前最先做的三件事：

1. 确定公司名称、注册地址、经营范围、股权结构和法定代表人，启动公司设立；
2. 公司主体确定后，核对微信 AppID、服务类目、备案、域名和 CloudBase 的归属关系；
3. 创建 `linkgen-staging` CloudBase 环境，按本文件的数据字典和权限矩阵改造真实后端，停止把本地演示数据当生产数据。
