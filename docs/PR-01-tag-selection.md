# PR-01：标签选中状态统一

## 背景

编辑名片和发起讨论页面都允许用户最多选择 3 个社群标签。此前点击标签只有短暂的点击反馈，选中后的持续状态不够明显，用户难以确认当前已经选中了哪些标签。

## 本次改动

- 保留现有标签数据和最多 3 个标签的业务规则，不改变标签文案或存储格式。
- 统一编辑名片、发起讨论两个页面的 `.choice.chosen` 视觉规则：
  - 使用负责人主线的 `--coral` / `--coral-soft` 颜色；
  - 增加外圈高光和轻微阴影，形成持续的选中层级；
  - 提升选中文字和 `#` 标记的字重；
  - 未选中状态仍保持原有布局和颜色；
  - 增加颜色、边框、阴影的短过渡，不增加“已选”文字，不改变组件尺寸。
- 增加 `scripts/validate-tag-selection.js`，对两个页面的选择约束、WXML 状态绑定和选中样式做静态验收。

## 验收清单

1. 点击任意未选标签后，标签保留珊瑚色背景、边框和高光。
2. 再次点击同一标签后，恢复未选中样式。
3. 第 4 个标签不会被选中，仍沿用最多 3 个标签提示。
4. 编辑名片和发起讨论的选中样式一致。
5. 页面布局、标签文案、负责人亮色主题的基础色值均未改动。

## 本地验证

```text
node scripts/validate-tag-selection.js
node --check pages/edit-profile/edit-profile.js
node --check pages/create-post/create-post.js
git diff --check
```

微信开发者工具中还需要手动验证：编辑名片页和发起讨论页分别点击、取消、达到 3 个上限，并确认返回页面后选中状态与计数一致。

## 范围边界

本 PR 只处理标签选择反馈，不包含通讯录筛选标签扩充、自定义标签弹窗、CloudBase、活动链接解析或主题切换。这些需求拆到后续独立 PR，避免一次合并覆盖多个验收范围。
