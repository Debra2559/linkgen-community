## 需求清单

### 1. 修复编辑名片标签没有持续选中效果

- 页面：`编辑名片` → `03 · 社群标签` → `选择最像你的 3 个词`。
- 现象：按下时有瞬时反馈，但松开后看不出哪些标签已选；计数可能变化，视觉状态却不明确。
- 目标：已选标签持续显示高对比底色、边框和勾选标记；取消后恢复未选状态；最多选择 3 个，达到上限时给出提示。
- 验收：选择、取消、达到上限、亮色/暗色主题、离开页面再返回均能正确显示。
- 归属：我们（前端缺陷修复，P0）。

### 2. 优化成员名片上的标签表现

- 页面：`成员名片`。
- 目标：标签更具识别性和层次，但不破坏负责人原有卡片结构。
- 初步设计：按标签类别使用图标/色点或低饱和分类色；保持文字可读性，不让颜色取代文字含义；同一标签在通讯录、编辑名片和成员名片中保持一致。
- 验收：亮暗主题均清晰；标签较多、较长时不会挤压主要信息；颜色符合对比度要求。
- 归属：我们（视觉与前端，P1）。

### 3. 扩充并统一通讯录筛选标签体系

- 当前筛选：全部、AI 产品、设计、独立开发、找搭子、线下活动。
- 问题：标签数量与粒度不足，而且编辑名片、成员名片、通讯录的命名并不完全统一。
- 建议先形成分组词表，而不是无限增加平铺胶囊：
  - 角色/能力：产品、设计、开发、运营、内容、研究、创业。
  - 方向：AI 产品、Agent、AI 编程、AI 绘画/视频、开源、用户研究。
  - 连接诉求：找搭子、求职/招聘、项目合作、经验交流、寻找用户。
  - 活动偏好：线下活动、线上分享、工作坊、共创。
- 首屏只展示高频筛选，更多标签通过“更多筛选”展开；标签由统一 ID 驱动，避免同义词造成数据碎片。
- 归属：我们做产品方案和前端；最终词表与负责人共同确认（P1）。

### 4. 完成“粘贴活动链接，一键解析”

- 页面：`提交活动`。
- 目标：粘贴微信公众号或小红书活动链接后，自动生成可编辑草稿，包括标题、简介、时间、地点、活动形式、封面、来源链接等。
- 交互：解析中、解析成功、部分字段缺失、链接不支持、解析失败都必须有明确反馈；解析结果必须让提交者确认和修改，不能直接发布。
- 技术拆分：前端负责粘贴、状态和草稿回填；云函数/服务负责抓取与结构化；平台不允许抓取时降级为手工填写或运营补录。
- 合规：不绕过登录、验证码、访问控制或平台限制；保留来源和抓取时间。
- 归属：我们负责产品、前端和接口约定；后端能力需与负责人协作（P1）。

### 5. 决定是否支持手机号/邮箱登录

- 当前结论：MVP **不建议**增加手机号或邮箱登录。
- 原因：微信小程序已经可以通过 `wx.login` + OpenID/UnionID 建立微信身份；手机号授权不是另一套登录，而是需要用户明确同意的补充信息；邮箱登录会增加密码、验证码、找回和跨端账号合并成本。
- 何时才需要：未来出现网页/APP 跨端账号、必须脱离微信登录、主办方实名联系或账号找回需求时再评估。
- 建议：MVP 使用微信身份 + 邀请/审核机制；手机号或邮箱只作为可选、默认不公开的联系方式，不作为进入社区的必要条件。
- 归属：产品决策需与负责人确认；账号和数据实现由负责人主导（P1，决策项）。

### 6. 补全“我的动态”

- 当前核查：页面、跳转、我发起的/我的回复两个 Tab、统计和空状态已经存在；数据仍来自本地模拟数据，并按昵称匹配用户，不是真实多用户动态系统。
- 缺口：真实用户身份、真实帖子/回复归属、分页、删除/编辑权限、从动态进入原帖、空状态后的完整闭环。
- 目标：先把前端页面和跳转闭环验收清楚，后续通过负责人提供的数据接口接入真实数据。
- 归属：我们负责前端闭环与接口需求；数据归属和权限由负责人后端实现（P1）。

### 7. 删除“我的”页面列表里的“我的名片”入口

- 原因：页面顶部已经展示可点击的数字名片，列表中的“我的名片”属于重复入口。
- 目标：删除该列表项，但保留顶部名片的查看/编辑路径；检查删除后列表圆角、分割线和间距。
- 归属：我们（前端，P1）。

### 8. 统一并补全运营管理

- 当前问题：采集、活动候选、审核、发布和异常处理没有形成统一工作台与状态流。
- 建议状态：候选 → 待补充 → 待审核 → 已发布 / 已驳回 / 已过期。
- 工作台至少包含：来源、解析状态、缺失字段、重复检测、负责人、审核记录、发布时间、失败原因和重试。
- 所有自动发现的内容只能进入候选池，必须人工确认后发布。
- 归属：我们负责流程、界面与接口需求；负责人负责数据库和后端权限（P1）。

### 9. 建立每日自动活动采集任务

- 来源目标：小红书、微信公众号，以及后续确认的公开活动源。
- 流程：定时发现 → 去重 → 解析 → 质量评分 → 候选池 → 人工审核 → 发布。
- 需要可配置：关键词、城市、来源账号/链接、运行频率、启停、失败重试、通知对象。
- 安全边界：不得绕过平台登录、验证码或访问限制；优先使用公开页面、授权接口、运营提供的来源清单；无法稳定自动化的来源保留人工粘贴入口。
- 归属：我们负责产品设计、前端运营台和任务接口；定时任务、采集服务及数据存储需负责人协作（P2，先设计后实现）。

### 10. 数据库由项目负责人负责

- 明确边界：我们暂不创建或直接变更生产数据库、集合和权限规则。
- 我们需要交付给负责人的内容：字段需求、实体关系、状态枚举、接口入参/出参、权限矩阵、索引与查询场景、迁移和验收样例。
- 负责人负责：CloudBase 集合/表、云函数、鉴权、数据安全规则、部署和生产数据迁移。
- 双方在联调前确认接口契约，避免前端字段与数据库实现各自演进。
