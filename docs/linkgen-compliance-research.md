# LinkGen 公开社区主体与备案调研

调研时间：2026-08-09

## 结论

详细的主体、数据、成员采集、内容治理、Agent 边界、工程改造和分阶段上线清单见[公开运营准备与执行路线](linkgen-public-operation-plan.md)。本文件保留主体与备案判断，避免把平台审核项误写成全国统一的法律结论。

个人主体可以注册部分微信小程序，但 LinkGen 当前功能包含公开成员目录、发帖、评论、活动提交和成员互动，不建议把个人主体作为正式运营主体。

推荐：使用公司或社会组织主体注册小程序；个人主体只适合内部试用、非公开 Demo，不能作为公开社区长期方案。

## 没有公司时的最优路径

| 路径 | 适用场景 | 判断 |
| --- | --- | --- |
| 个体工商户 | 低成本验证、无收费、邀请制、官方内容为主 | 可作为 MVP，但经营者承担个人责任，社交/社区类目和许可证仍可能受限 |
| 一人有限责任公司 | 已决定公开运营，包含发帖、评论、成员目录和活动 | 推荐；主体清晰、可签合同和收款，后续申请资质不需要再次迁移主体 |
| 借用朋友公司 / 买现成主体 | 想快速上线 | 不推荐；实际运营者、用户数据责任和备案主体不一致，后续迁移成本高 |

最终建议：如果 LinkGen 只是验证需求，先注册个体工商户并把产品做成邀请制；如果目标是公开运营社区，直接注册一人有限责任公司。不要用个人主体上线完整的公开发帖和评论功能。

## 公开上线步骤

1. 确定主体：一人有限责任公司；经营范围由当地市场监管和代办会计按实际业务确认。
2. 用公司主体注册微信公众平台和小程序，后台选择与实际功能一致的服务类目。
3. 通过微信公众平台和工信部备案系统完成小程序/互联网信息服务备案。
4. 在提交“社交/社区/论坛/笔记/问答”等类目时，逐项确认是否要求增值电信业务经营许可证等资质。
5. 首发采用邀请制和人工审核，暂不开放广告、会员、打赏、付费活动；完成内容安全验证后再公开扩量。

## 原因

| 问题 | 对 LinkGen 的影响 |
| --- | --- |
| 服务类目 | 当前产品更接近“社交 / 社区 / 论坛 / 笔记 / 问答”类目，个人主体可选类目与资质范围受限，以微信公众平台后台实时清单为准 |
| UGC 内容 | 发帖、回复、留言属于互联网跟帖评论服务场景，需要后台实名、内容审核、实时巡查、投诉举报、违规处置和记录留存 |
| 公开通讯录 | 成员名片中的姓名、头像、城市、身份、联系方式属于个人信息，必须最小化采集、明确告知、取得同意并支持撤回/删除 |
| 运营主体 | 如果后续出现会员费、广告、赞助、付费活动或其他经营行为，个人主体在合同、收款、发票、资质和责任承接上都不适合作为平台主体 |
| 备案 / 许可 | 小程序上线需要按微信公众平台和工信部备案系统的当前要求办理；是否需要增值电信业务经营许可证，取决于实际类目、经营方式和属地通信管理局口径，不能仅凭“是小程序”判断 |

## 当前版本需要补齐

1. 后台实名：微信身份认证只用于登录不够，需要记录可审计的主体身份状态。
2. 内容审核：敏感词、图片/链接审核、举报、屏蔽、删除、封禁、操作日志。
3. 用户协议与隐私政策：说明帖子公开范围、成员名片字段、活动信息、联系方式交换规则。
4. 名片权限：默认只展示昵称、头像、城市、身份、标签和目的；微信号、手机号必须单独授权，不直接公开。
5. 审核后台：活动审核之外，补充帖子审核、举报处理、成员封禁和导出审计记录。
6. 数据存储：当前项目使用本地 Storage，仅能做 Demo；公开运营必须切换到云数据库和服务端权限控制。

## 推荐落地顺序

`内部 Demo --(企业/组织主体注册)--> 小程序备案 --(类目审核)--> 灰度邀请 --(内容安全验证)--> 公开运营`

首版建议先做“社群成员可申请加入”的半公开模式：需要审核入群，成员目录登录后可见，帖子允许发布但必须先过审核；完成稳定运营后再开放全网访问。
