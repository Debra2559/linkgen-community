# LinkGen Agent 与学习库落地方案

## 结论

采用两条配合的产品链路：

1. **活动 Agent**：负责发现、解析、筛选和提醒；不自动发布。
2. **学习库**：负责资料目录、摘要、搜索、收藏和外部入口；不复制外部全文。

学习库采用混合承载：小程序做目录和发现，飞书做协作长文，LinkGen 公众号做公开观点，原官方网站做工具和课程的权威入口。

## 为什么不是全部放小程序

| 方案 | 优点 | 问题 | 判断 |
| --- | --- | --- | --- |
| 全部放小程序 | 体验统一 | 编辑、版本、权限、全文阅读和审核成本高；外部内容还有版权风险 | 不采用 |
| 全部放公众号 | 发布简单、公开传播方便 | 搜索和分类弱，成员投稿与权限管理不适合 | 不采用 |
| 全部放飞书 | 协作和知识库能力强 | 新成员发现成本高，社群内容和公开内容混在一起 | 不采用 |
| 小程序目录 + 外部承载 | 发现快、维护成本可控、便于权限分层 | 依赖链接和业务域名配置 | **采用** |

## 内容分层

| 内容 | 目录字段 | 实际承载 |
| --- | --- | --- |
| LinkGen 活动复盘、方法清单 | 摘要、标签、维护人 | 飞书文档 |
| 公开观点、精选文章 | 摘要、来源、原文链接 | LinkGen 公众号或原公众号 |
| API、课程、工具说明 | 适用人群、阅读时长、官方来源 | 原官方网站 |
| Agent 发现的分享 | 文章概要、平台、质量分、原文链接 | 先进入草稿，人工发布 |
| 帖子中的短经验 | 帖子标签和资料关联 | 小程序帖子，不重复维护全文 |

## 活动 Agent 状态机

```text
来源配置
  --(每日 09:00，逐个授权 URL)--> 抓取与解析
  --(活动/分享分类)--> 候选或分享归档
  --(质量、未来时间、去重校验)--> 待审核活动
  --(微信订阅消息)--> 管理员待处理
  --(管理员通过)--> events / 活动页
  --(管理员驳回)--> rejected / 审计日志
```

分享不进入活动审核队列，而是保存在 `source_items`，运营可以点击“收录”生成学习库草稿。

## 当前已实现

| 链路 | 实现位置 | 结果 |
| --- | --- | --- |
| 来源池 | `agent_sources`、运营页 | 8 个预置观察来源：4 个公众号、1 个小红书观察池、3 个搜索/发现入口；每个来源支持多个 URL 或关键词 |
| 用户链接解析 | `parseActivityLink`、活动创建页 | 服务端解析公开公众号/小红书页面，返回标题、概要、时间、地点、封面和报名入口 |
| 关键词发现 | `activityAgent` + Bing Web Search API | 可选按关键词发现公开页面，再回原站核验；无密钥时跳过 |
| 定时巡查 | `cloudfunctions/activityAgent` | 每天 09:00；超时、SSRF、跳转和内网地址检查 |
| 内容解析 | JSON-LD、Meta、页面标题和规则 | 标题、摘要、封面、时间、地点、主办方、原文链接 |
| 分类与质量 | `activityAgent` | `activity` / `share`、质量分、字段证据和风险标记 |
| 去重 | `contentHash`、`canonicalUrl` | 同一来源重复巡查不重复生成候选或通知 |
| 审核 | `approveActivityCandidate`、`rejectActivityCandidate` | 通过才写入 `events`，保留审计日志 |
| 活动展示 | `listPublishedEvents`、`getPublishedEvent` | 活动列表、详情、图片、来源摘要和原文链接从云端读取 |
| 报名 | `registerForEvent` | 社区活动报名、满员、取消报名和人数事务更新 |
| 封面补充 | `updateActivityCandidate` | 管理员上传到 Cloud Storage，审批后可直接用于活动封面 |
| 学习库 | `pages/library`、`pages/library-detail`、`library_resources` | 精选、分类、搜索、详情、收藏、外部链接复制 |
| 学习库运营 | `pages/library-admin` | 新增、编辑、发布、下线、精选和访问范围管理 |
| 资料维护 | `libraryMaintenance` | 每周检查来源链接；失效链接或 90 天未更新资料进入 `needs_recheck`，保留链接状态和审计记录 |

## 平台接入边界

公众号和小红书不能仅凭账号名称实现稳定、合法的全网抓取。生产来源按以下优先级接入：

1. LinkGen 自有内容、主办方授权 Feed 或官方 API。
2. 官方网站、RSS/Atom、sitemap、JSON-LD Event 页面。
3. 管理员主动粘贴的公众号/小红书文章或笔记链接。
4. 合作方提供的活动列表接口。

关键词搜索只作为发现层，不把搜索结果直接当作事实；结果必须回到原始页面解析，并经过时间、地点、链接和管理员审批。

不绕过登录、验证码、频控或反爬；不在小程序前端保存第三方 Cookie、密钥或登录态。外部图片与摘要只在有展示权限时使用，正式发布前由管理员确认。

## 上线前配置

| 顺序 | 操作 | 验收结果 |
| --- | --- | --- |
| 1 | 开通 CloudBase，部署 Agent、活动、学习库相关云函数 | 运营页显示 CloudBase 实时数据 |
| 2 | 创建 `admins`、`agent_settings`、`agent_sources`、`source_items`、`activity_candidates`、`agent_runs`、`events`、`event_registrations`、`audit_logs`、`library_resources`、`library_saves` | 集合权限正确，普通用户不能写运营集合 |
| 3 | 导入 `db-import/agent-sources.json` | 观察池显示公众号和小红书来源 |
| 4 | 为每个来源填入授权 URL，设置 `authorizationStatus` | 手动巡查可读取来源 |

| 6 | 手动巡查，检查候选图片、概要、时间、地点、原文链接 | 候选字段可人工核验 |
| 7 | 通过候选，检查活动页、来源卡片和报名人数 | 审批后真实出现在活动页 |
| 8 | 在资料库发布一条飞书文档 | 学习库可搜索、收藏、复制入口 |

## 资料维护规则

- 外部资料只保存必要的标题、摘要、封面和原始链接，不复制全文和评论。
- 资料必须有摘要、来源和维护人；外部链接失效后下线入口并保留审计记录。
- 连续 90 天未更新的技术资料进入待复核。
- 成员投稿先进入草稿，不能直接出现在精选列表。
- `public` 资料可公开访问；`member` 资料只有 `users.status=active` 的成员可见。
