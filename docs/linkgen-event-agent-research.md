# LinkGen 活动采集 Agent 调研

> 调研日期：2026-08-11
>
> 结论：可以做，但不应把小红书和微信公众号当成可无限抓取的公共数据库。首版优先采集官方网站、RSS/Atom、活动页和用户主动提交的链接；平台内容采用授权接入或人工核验。

## 一、产品定位

Agent 只负责发现、解析和整理候选活动，不负责自动发布。

```text
来源白名单
  -> 定时任务
  -> 抓取/授权接口
  -> 活动字段提取
  -> 时间、链接、来源校验
  -> 相似活动去重
  -> 运营审核
  -> 社区活动 / 精彩活动
```

状态机：

```text
发现 --(解析成功)--> 待审核
待审核 --(官方通过)--> 已发布
待审核 --(驳回)--> 未通过
已发布 --(报名链接失效/来源撤稿)--> 待复核
已发布 --(活动结束)--> 已结束
```

## 二、来源可行性

| 来源 | 首版方式 | 自动化程度 | 主要限制 | 建议 |
|---|---|---:|---|---|
| 官方网站、活动主办方页面 | RSS/Atom、sitemap、JSON-LD Event、公开 API、白名单页面 | 高 | 页面结构变化、来源质量不一 | 第一优先级 |
| 微信公众号文章 | 用户粘贴文章链接；主办方授权后接入 | 中 | 任意公众号文章没有稳定的公开全文搜索接口；授权、转载和版权边界需确认 | 先做链接导入 |
| 小红书笔记 | 用户粘贴笔记链接；合作方授权后接入 | 低到中 | 公开开发者能力不等于任意公开笔记搜索权限；登录态、反爬和转载限制明显 | 不做无授权爬虫 |
| 搜索引擎结果 | 关键词发现链接，再回到原站核验 | 中 | 结果不等于事实；有配额、费用和误报 | 作为发现层，不作为内容源 |
| 合作活动平台 | API、RSS 或主办方 feed | 高 | 需要合作、授权和字段映射 | 第二阶段接入 |

已核对的官方入口：

- [微信服务号文档](https://developers.weixin.qq.com/doc/service/guide/)
- [微信素材管理文档](https://developers.weixin.qq.com/doc/service/guide/product/asset.html)
- [小红书开放平台](https://open.xiaohongshu.com/)

官方文档中的 API、素材或授权能力，不能推导出“可以搜索并转载所有公开内容”。每个来源上线前都要记录授权状态、允许字段、调用频率和下线机制。

## 三、推荐系统架构

```text
Cloud Scheduler / Cron
        |
        v
Source Registry -----> Fetcher / Authorized Connector
        |                         |
        |                         v
        +-----------------> Extractor
                                  |
                          Normalize + Validate
                                  |
                          Deduplicate + Score
                                  |
                           Candidate Queue
                                  |
                    Admin Web: 核验、编辑、合并、发布
                                  |
                      Cloud Function -> 小程序活动库
```

### 组件职责

| 组件 | 职责 |
|---|---|
| Source Registry | 来源 URL、平台、关键词、城市、授权状态、抓取频率、负责人 |
| Scheduler | 按来源执行任务；错峰、限速、失败重试；不在小程序端运行 |
| Fetcher | 只访问白名单 URL；检查 robots、跳转和响应类型；阻止内网地址 |
| Extractor | 先用 JSON-LD/DOM/正文规则提取，再用模型补缺；每个字段输出证据和置信度 |
| Validator | 校验未来时间、报名链接可达、地点完整、主办方和来源一致 |
| Deduplicator | URL 规范化、内容 hash、标题/时间/城市/主办方相似度合并 |
| Candidate Queue | 保存候选和原始来源，不直接写入已发布活动 |
| Admin Web | 展示原文链接、字段证据、风险项和变更记录，供官方审核 |

## 四、数据字段

### source_items

| 字段 | 说明 |
|---|---|
| `source_url` | 原始来源 URL |
| `canonical_url` | 去参数、去追踪字段后的规范 URL |
| `source_platform` | `official_site`、`wechat`、`xiaohongshu`、`search` |
| `authorization_status` | `owned`、`authorized`、`public_link`、`unknown` |
| `fetched_at` | 最近抓取时间 |
| `content_hash` | 用于幂等和重复判断 |
| `raw_title` / `raw_excerpt` | 只保存活动必要的最小原文 |
| `http_status` / `last_verified_at` | 来源可用性追踪 |

### activity_candidates

| 字段 | 说明 |
|---|---|
| `title`、`description` | 可编辑活动信息 |
| `start_at`、`end_at` | 标准化后的时间，保留原始时间文本作证据 |
| `location_mode`、`city`、`venue` | 线上/线下、城市、场地 |
| `organizer`、`registration_url` | 主办方和报名入口 |
| `expected_count` | 预计人数；外部活动可为空 |
| `scope` | `community` 或 `featured` |
| `confidence` | 整体置信度，不替代人工审核 |
| `field_evidence` | 每个字段对应的原文片段或 DOM 定位 |
| `risk_flags` | 时间不完整、链接失效、疑似广告、内容不足等 |
| `review_status` | `pending`、`approved`、`rejected`、`needs_recheck`、`expired` |

## 五、与 LinkGen 活动规则的衔接

| 类型 | 发布后的用户操作 |
|---|---|
| 社区活动 | 官方发布；可报名；统计人数；达到上限后自动变为“已满” |
| 精彩活动 | 只允许“加入日程”；展示原始报名链接；不在 LinkGen 内统计报名人数 |
| 来源失效 | 自动进入“待复核”；暂停推荐，不自动删除历史记录 |

Agent 发布状态机：

```text
候选活动 --(官方审核)--> 社区活动 --(报名满额)--> 已满
候选活动 --(官方审核)--> 精彩活动 --(点击加入日程)--> 已加入日程
```

## 六、必须控制的风险

| 风险 | 控制措施 |
|---|---|
| 平台规则/反爬 | 来源白名单、授权凭证、限速、robots 和服务条款记录；禁止绕过登录和验证码 |
| 版权 | 默认只展示摘要、结构化字段和原始链接；不长期转载全文、图片和评论 |
| AI 误抽取 | 原文证据、字段置信度、缺失字段提示；时间、地点、报名链接必须人工确认 |
| 网页提示注入 | 页面正文只当作不可信数据，不能触发 Agent 工具调用、改权限或发消息 |
| SSRF | 服务端只允许 `http/https`，解析跳转前后域名，禁止访问内网、文件和云元数据地址 |
| 重复活动 | URL 规范化 + 内容 hash + 标题/时间/城市/主办方相似度；合并由运营确认 |
| 过期信息 | 定期检查报名链接和活动状态；活动前 24 小时、结束后分别复核 |

## 七、落地路线

| 阶段 | 内容 | 结果 |
|---|---|---|
| 1 | 官方网站白名单 + RSS/JSON-LD/DOM 解析 + 人工审核 | 获得第一批真实活动 |
| 2 | 用户粘贴公众号/小红书链接，服务端解析可访问的公开元数据 | 替换当前本地演示解析 |
| 3 | 定时 Agent、候选队列、去重、失效检测、审计日志 | 形成稳定采集流程 |
| 4 | 与主办方或活动平台签授权/API 合作 | 扩大公众号和小红书覆盖 |

最小可行版本不需要一开始搜索全网：先配置 10-20 个高质量官方网站和主办方来源，按城市与关键词每天 2-4 次采集；每次先入候选队列，运营审核后发布。

## 八、对当前实现的判断

当前仓库已经把生产链路的代码骨架接入 CloudBase：

1. `activityAgent` 承载定时任务、解析、去重、质量评分和通知。
2. `source_items`、`activity_candidates`、`agent_runs`、`audit_logs` 保存来源、候选、运行和审批记录。
3. 运营页支持来源配置、手动巡查、候选核验、封面上传和分享收录。
4. 通过后写入 `events`；小程序活动页只读取已发布活动。

可选的 `kind=search` 来源已支持 Bing Web Search API：它只负责发现候选 URL，随后仍需回到原始页面解析和人工审核；没有 `BING_SEARCH_KEY` 时不会执行搜索。

未完成的不是本地演示逻辑，而是生产配置：CloudBase 部署、授权来源 URL、通知模板、业务域名和平台合作接口。未完成配置前，页面明确回退到本地演示数据。

本调研不是法律意见。涉及平台授权、内容转载、个人信息和公开运营时，应以平台最新协议、合作合同和专业法律意见为准。
