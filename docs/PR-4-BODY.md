## 这次 PR 是什么

这是 LinkGen 前九项需求的**本地前端实现 + CloudBase 联调准备**，不是生产上线 PR。

所有代码来自独立分支 `codex/dark-theme`。请负责人先按文档和测试环境验收，再决定是否合并到 `main`。本 PR 不会自动发布体验版，也不会修改正式数据库。

## 前九项需求完成情况

### 1. 编辑名片标签持续选中反馈

- 选中后持续显示主题色背景、对比边框和高光，不再只有点击瞬间反馈。
- 暗色主题使用紫色；亮色主题使用橘色。
- 取消后恢复未选状态。
- 最多选择 3 个标签，达到上限会提示。
- 增加“自定义标签”，限制 12 个字符并防止重复。
- 自定义标签弹层使用 LinkGen 自己的主题化 UI，不使用微信默认白色 `showModal`。

### 2. 成员名片标签视觉

- 标签按角色与能力、关注方向、连接诉求、活动偏好做语义分组。
- 使用颜色圆点和低饱和胶囊表达类别，文字仍是主要信息。
- 亮色/暗色主题均保持可读，不改变负责人原有名片结构。

### 3. 通讯录筛选标签扩充

- 首屏保留高频标签：全部、AI 产品、Agent、设计、独立开发、找搭子、线下活动。
- 增加“更多筛选”，按分组展开角色、方向、连接诉求和活动偏好。
- 增加清除筛选入口。
- 增加标签别名归一化，避免“AI 工具/AI 应用”等同义词造成数据碎片。
- 最终标签词表仍需负责人和运营共同确认。

### 4. 提交活动一键解析

- 前端已经有解析中、成功、部分字段缺失、失败和未连接云端状态。
- 未连接解析服务时只识别来源，不生成虚假活动草稿，提示用户手工填写。
- `parseActivityLink` 云函数已有安全 URL 校验、结构化草稿和风险字段代码。
- 真实公众号/小红书解析需要测试环境、服务部署和合规确认，尚未宣称生产可用。

### 5. 手机号/邮箱登录讨论结论

当前 MVP **不增加手机号/邮箱作为登录方式**：

- 小程序已有微信登录，可用 OpenID/UnionID 建立社区身份。
- 手机号适合作为用户主动公开的联系方式，不应默认公开或成为入群门槛。
- 邮箱登录会增加验证码、找回、跨端账号合并和隐私成本。
- 只有未来需要网页/APP 跨端账号、脱离微信登录或实名联系时再重新评估。

### 6. 我的动态

- “我的动态”页面和入口已存在并完成本地闭环。
- 支持“我发起的 / 我的回复”两个视图、统计、空状态和进入原帖。
- 本地数据优先用 `memberId` 判断归属，同时兼容旧昵称数据。
- 增加本地删除讨论闭环。
- 真实多用户数据、OpenID 归属、分页和云端删除权限需 CloudBase 联调。

### 7. 删除重复的“我的名片”入口

- 删除“我的”页面列表中的重复“我的名片”项。
- 保留顶部数字名片的查看和编辑路径。
- 已检查列表间距、圆角和分割线。

### 8. 运营管理工作台

- 增加候选状态筛选：待审核、待补充、已发布、已驳回、全部活动。
- 增加“待补充”动作，可填写原因并记录本地状态。
- 云端 `updateActivityCandidate` 支持 `needs-info` 操作并写入审核日志。
- 工作流约定为：候选 → 待补充 → 待审核 → 已发布/已驳回/已过期。
- 自动发现内容仍只能进入候选池，必须人工审核后发布。
- 编辑补充资料和重新提交需要后端接口后继续完成。

### 9. 每日自动活动采集

- `activityAgent` 云函数代码和每日 09:00 定时触发器骨架已存在。
- 采集流程已按“发现 → 去重 → 解析 → 质量评分 → 候选池 → 人工审核”设计。
- 来源支持页面链接、授权 Feed 和关键词搜索三类配置。
- 默认不启用正式定时采集；小红书、公众号来源需要公开可访问/授权来源和合规确认。
- 测试环境先手动运行，确认只写入 `activity_candidates`，再讨论正式启用。
