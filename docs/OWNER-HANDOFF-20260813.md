# LinkGen 独立分支负责人交接说明

> 这份说明给项目负责人看。目标是让负责人先了解改动、确认边界，再决定是否合并；本分支不要求立即合并到 `main`。

## 一句话结论

本分支完成了当前不依赖正式 CloudBase 环境的前端和本地原型工作，并补齐了数据库/云函数联调所需的接口与字段约定。真实数据库、云函数部署和正式环境上传仍由负责人控制。

## 从哪里开始看

1. `docs/PRODUCT-TASKS-20260813.md`：10 项需求的逐项状态和未完成边界。
2. `docs/CLOUDBASE-TEST-ENV-REQUEST.md`：测试环境、集合、字段、索引、权限和验收顺序。
3. `git diff main...codex/dark-theme`：本分支相对主线的完整差异。
4. 最近提交：`878c807`（主题化自定义标签弹层）；前置提交包含本地流程和云函数骨架。

## 本分支已经做的事

- 名片标签：持续选中状态、统一亮/暗主题颜色、自定义标签入口和主题化弹层。
- 成员名片：标签按角色、方向、连接诉求、活动偏好做语义化视觉区分。
- 通讯录：高频标签、更多筛选、分组筛选和清除筛选。
- 活动提交：解析中/成功/缺字段/失败/未连接云端的状态边界；离线时不会伪造解析草稿。
- 我的动态：本地本人识别、我的发起/回复、删除讨论闭环。
- 运营审核：状态筛选和“待补充”动作；本地与云端接口均保留明确状态。
- `manageCommunityContent`：测试环境用的用户资料、我的动态、发帖、回复、点赞云函数代码骨架。
- 文档：数据表、字段、索引、权限、验收顺序和发布闸门。

## 负责人需要决定/执行的事

### 先创建测试环境

- 创建独立 CloudBase 测试环境，并提供环境 ID、地域和测试管理员配置方式。
- 测试环境使用与正式环境隔离的数据；定时采集默认关闭。
- 确认测试集合和云函数部署权限，不要先操作正式数据。

### 再做联调确认

- `users` 的稳定 `memberId` 生成方式是否接受。
- `posts`、`post_comments`、`post_likes` 的字段和权限是否接受。
- `activity_candidates` 的 `pending / needs_info / approved / rejected` 状态是否接受。
- `parseActivityLink` 的公开链接范围、失败策略和合规边界。
- 首期管理员、通知对象、来源授权和自动采集频率。

### 最后决定是否合并

- 先在测试环境验收，再决定是否合并到 `main`。
- 由负责人执行体验版上传；本分支不直接上传正式 AppID 的开发版本。
- 若主线在此期间继续变化，先同步主线并重新检查冲突，不要直接覆盖负责人的新 UI。

## 本地验证

在 `linkgen-miniapp` 目录执行：

```powershell
node scripts/validate-linkgen-release.js
node tests/community-data.test.js
```

当前结果：发布结构检查通过（17 个云函数），社区数据测试通过（17 条断言）。微信开发者工具的真实云端验收，需要测试环境创建后进行。

## 合并安全边界

- 工作分支：`codex/dark-theme`。
- 所有改动通过 PR 评审，不直接推送或合并 `main`。
- 本分支没有生产数据库凭据，也没有部署测试云函数。
- 本地 `project.config.json` 的测试 AppID 和 `project.private.config.json` 属于本机配置，未作为本次功能提交的一部分。
