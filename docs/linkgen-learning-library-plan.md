# LinkGen 学习库方案

## 结论

采用“**小程序做目录和发现，飞书/公众号做长内容承载**”的混合方案。

不建议把所有资料全文放进小程序，也不建议只丢一个公众号菜单。小程序负责让成员快速找到资料、看懂价值、收藏和跳转；飞书适合团队协作编辑和权限管理，公众号适合公开发布和沉淀品牌内容。

## 内容分层

| 内容 | 推荐承载 | 小程序展示 |
| --- | --- | --- |
| 一页清单、活动复盘、社群方法 | 飞书文档 | 摘要、标签、更新时间、飞书入口 |
| 面向公众的观点和长文 | LinkGen 公众号 | 摘要、封面、公众号文章入口 |
| 官方 API、公开课程、工具文档 | 原始官方网站 | 简介、适用人群、原始链接 |
| 成员共创资料 | 飞书知识库 | 草稿/审核状态、贡献者、版本记录 |
| 高质量公众号/小红书分享 | 原始文章/笔记链接 | 摘要、来源、标签，人工收录后进入学习库草稿 |
| 帖子里的短经验 | 小程序帖子 | 通过标签关联到资料卡，不重复维护全文 |

## 资料卡字段

```text
title              标题
summary            80-140 字摘要
category           入门 / Agent / 产品 / 独立开发 / 社群沉淀
tags               2-4 个标签
source_type        飞书文档 / 公众号文章 / 官方文档 / 公开课程
source_url         外部链接
cover_image        封面，可选
owner              维护人
updated_at         最近更新时间
review_status      draft / published / archived
access_policy      public / member / admin
```

## 发布规则

1. 资料卡必须有摘要、来源和维护人；没有来源的内容标记为社群原创，不伪装成外部资料。
2. 外部内容只保存必要的标题、摘要、封面和原始链接，不复制全文和评论。
3. 飞书文档和公众号文章发布前由管理员确认访问权限、版权和链接有效性。
4. `libraryMaintenance` 每周将连续 90 天未更新的技术资料标记为 `needs_recheck`；链接失效或来源撤稿后下线入口但保留审计记录。
5. 成员投稿进入草稿，不直接出现在公开精选列表。

## 产品形态

当前实现已覆盖：

- 发现页固定入口，不新增底部 Tab。
- 精选、全部、社群沉淀、入门、Agent、产品、独立开发分类。
- 标题/摘要/标签/来源搜索。
- 点击资料卡进入详情页，查看摘要、来源、维护人、更新时间和收藏状态。
- 资料卡收藏。
- 外部资料复制链接；配置合法业务域名后再切换为 `web-view`。
- CloudBase 优先读取已发布资料，未部署时回退本地演示资料；收藏通过 `library_saves` 保存。
- 运营管理页增加资料库管理入口，支持新增、编辑、发布、下线和精选标记。
- 官方文档使用真实公开链接；内部资料没有入口时明确显示“等待发布”，不使用虚假链接。

后续版本建议增加：

- 资料详情页，展示版本、维护人、适合人群和相关帖子。
- `web-view` 打开已配置业务域名的飞书中转页或 LinkGen 内容页。
- 管理员 Web 后台批量导入、链接巡检和批量更新资料。
- 资料与活动、帖子、成员标签互相推荐。

访问范围：`public` 资料对公开用户可见；`member` 资料只有 `users.status=active` 的成员可见。未完成真实成员后端前，不发布 `member` 资料，避免把“登录用户”误当成“社群成员”。

## 维护流程

```text
成员投稿 --(管理员初审)--> 草稿
草稿 --(补齐来源/摘要/权限)--> 待发布
待发布 --(发布)--> 学习库
学习库 --(链接巡检/90天复核)--> 正常 / 待复核 / 已下线
```

## 版本建议

| 版本 | 内容 | 目标 |
| --- | --- | --- |
| MVP | 目录、搜索、分类、收藏、外链、基础资料管理 | 验证成员是否真的使用资料库 |
| V1 | 管理 Web 后台、飞书权限、版本和失效巡检 | 保证资料质量和可维护性 |
| V2 | 投稿、共创、资料与帖子/活动关联 | 形成社群知识沉淀 |
