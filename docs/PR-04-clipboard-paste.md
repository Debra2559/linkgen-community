# PR-04：发起讨论的剪贴板粘贴兜底

## 背景

发起讨论页的“粘贴链接”依赖 `wx.getClipboardData`。在游客模式、开发者工具或系统剪贴板权限异常时，读取可能失败；原流程只提示一次 toast，用户没有继续输入的入口。另一个常见情况是从浏览器复制的链接不带 `https://`，会被误判为无效。

## 本次改动

- 增加统一链接标准化：缺少协议头时自动补全 `https://`。
- 剪贴板读取成功后，继续复用现有图片、视频和普通链接附件逻辑。
- 剪贴板为空、内容不是网页链接、API 不可用或读取失败时，自动打开手动链接面板，并给出可继续操作的提示。
- 手动保存链接也复用同一套标准化和网页链接校验，避免两条路径规则不一致。
- 不改变附件数据结构、去重规则、发布流程或 CloudBase 代码。

## 验收清单

1. 复制带 `https://` 的公众号、小红书或普通网页链接，点击“粘贴链接”后能进入链接面板。
2. 复制不带协议头的 `mp.weixin.qq.com/...` 或 `xhslink.com/...`，仍能自动补全并进入链接面板。
3. 剪贴板读取失败时，页面打开手动输入面板，而不是停留在原页面。
4. 剪贴板内容不是链接时，提示原因并保留手动粘贴入口。
5. 手动输入后点击“添加链接”，行为与原附件流程一致。

## 本地验证

```text
node scripts/validate-clipboard-paste.js
node scripts/validate-linkgen-release.js
node --check pages/create-post/create-post.js
git diff --check
```

微信开发者工具中还需要手动覆盖：正常剪贴板、空剪贴板、不带协议头的链接、非链接文本和读取失败五种情况。开发者工具无法稳定模拟失败时，至少验证手动面板和不带协议头链接。

## 范围边界

本 PR 只处理发起讨论页的剪贴板读取和手动粘贴体验，不承诺对公众号或小红书正文做服务端解析。提交活动页的 CloudBase `parseActivityLink` 仍属于负责人主线的独立联调范围。
