# PR-07：手机号 / 邮箱登录决策

## 结论

LinkGen 当前阶段不新增手机号或邮箱登录。首版使用微信登录识别用户即可；手机号和邮箱只在明确出现跨端账号、找回账号或通知触达需求后再评估绑定功能。

## 为什么首版不加

- 小程序的核心身份已经由微信 `openid` 提供，社群用户不需要再填写第二套账号。
- 手机号和邮箱都属于额外个人信息，需要收集说明、授权、校验、脱敏和删除机制。
- 验证码、账号合并、换绑、找回和重复账号会增加后端表结构、云函数和运营支持成本。
- 当前产品目标是打通群之间的活动、通讯录和讨论，不是做跨平台账号体系。

## 推荐方案

### 当前版本

1. 继续使用微信登录作为唯一必需身份。
2. 用户资料使用微信登录后的内部用户标识关联，不在前端保存手机号或邮箱。
3. 需要联系用户时，先使用小程序订阅消息和微信内入口。

### 后续触发条件

只有在以下任一条件成立时，才新开需求评估“绑定手机号”，而不是直接做双登录：

- 同一用户需要在网站、飞书或其他客户端查看同一份资料；
- 需要短信作为高价值活动的报名确认或紧急通知；
- 用户明确提出账号迁移、找回或跨微信账号合并需求。

届时优先设计“微信登录 + 可选绑定手机号”，邮箱登录继续延后，除非已经有明确的网页端用户场景。

## 不在本 PR 中做的事

- 不新增手机号或邮箱输入框。
- 不新增验证码、账号密码或找回流程。
- 不修改 `login` 云函数、用户表或权限模型。
- 不改变当前微信登录验收流程。

## 负责人需要确认

请在 PR 中确认：首版是否接受“微信登录唯一身份，手机号/邮箱暂缓”的结论。若接受，后续 CloudBase 设计按 `openid` 作为用户主键；若不接受，需要先补充跨端场景、数据保留周期、短信服务和账号合并规则，再单独开实现 PR。
